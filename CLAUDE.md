# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

The server lives in `server/` (Node ≥ 23.6, TypeScript run directly, no build step).

```bash
./start.sh                      # from repo root: frees port 4400 and starts the server (http://127.0.0.1:4400); start.cmd on Windows
cd server && npm install        # first time only
cd server && npm start          # same server without the port-cleanup step
cd server && npm run check      # tsc --noEmit (type check only)
cd server && npm test           # test/run.mjs: node --test test/ (with WORKSPACE set to a temp dir) + the python tests in test/
cd server && node --test test/lib.test.ts          # single TS test file
cd server && node --test --test-name-pattern="spansFromWords" test/lib.test.ts   # single test by name
cd server && python3 test/test_pace.py             # single Python test
```

Environment variables read by the server and pipeline: `PORT` (default 4400), `WORKSPACE` (default `workspace/`), `CLAUDE_BIN` (path to the `claude` CLI used for model calls), `REEL_LANG` (default `pt`, passed to Whisper), `YT_DLP` (default `yt-dlp` from PATH), `CLAUDE_TIMEOUT_MS` (default 20 min per model call), `PYTHON` (interpreter name, default `python3`, `python` on Windows), `CHROME_PATH`. `../.env` is loaded if present.

## Architecture

**Two halves, one pipeline.** `server/` is an HTTP + SSE orchestrator with a single-file UI (`server/ui.html`, no build). The heavy media work is done by scripts in `claude-reel-editor/skills/reel-editor/scripts/` (Python, one Swift file for Vision face/nose tracking), which the server spawns. The `claude-reel-editor/skills/reel-editor/SKILL.md` describes the same workflow for use as a Claude Code skill; the server does not read it beyond locating the scripts.

**Request flow.** `server/server.ts` has a flat route table (`[method, regex, handler]`) that maps each endpoint to a function in `server/pipeline.ts`. `GET /projects/:id/events` is an SSE stream of step progress; the UI subscribes to it.

**Pipeline state machine (`server/pipeline.ts`).** Each project moves through steps: ingest → script → brand → motion → edit/batch → final, plus side branches `ae` (After Effects export) and `embrulhos` (hook variants). Every step is wrapped in `locked(id, step, fn)`, which allows only one step per project at a time and emits start/done/error events. `state.json` holds the project state and the cost log.

**One render path.** Every reel is composed by the agent composer; the card pipeline (edit.json, build_reel.py, validate.ts card checks, b-roll fill, illustration packs) was deleted in 00.22. The motion step sets up `<project>/compose/` (kit, guides, assets, auto-written `brief.md`), has Opus write `treatment.md` (the director, one call at medium effort) and then `compose/scenes.py` (which writes `compose/index.html`), and does not render: `final()` renders `compose/out.mp4`. The visual pieces come from the reel's asset library; `compose/engines/*.js` are drawing engines the kit's `canvas(..., engine=)` loads (copied into every compose/). The compose call has a hard `--max-turns` ceiling (`COMPOSE_MAX_TURNS`, default 70) and the prompts cap the snapshot-review loop at 2 rounds. The brief sets no quotas (no minimum images, camera moves or typography per scene): it demands fluidity, the safe zone, nothing over the face and the speaker reframed on `faceX`; `kit.py`'s lint no longer warns about camera counts. A format with `speaker: false` (Só Motion) composes with no speaker on screen (`noSpeaker` in `composeScaffold`/`composeRun`, same folder `compose/`); `mode === 'motion'` is still the no-speaker *test* that renders `preview-motion.mp4` from `compose-motion/`. A format is a palette of speaker shots plus an agenda (v9): `planos` (the kit's `cam` values `cut`, `panel`, `panel-top`, `raw`, `none`, `react`; `kit.py` lints a scene outside them), `janelas` (`null` = free agenda, or `{cut: [[0,5],["tail",5]]}`), `regras` (only the *when*), `panel` {side, top}, `safeZones`; `raw` and `react` scenes use `bg='clear'` so the video shows through, and `react` needs the project's reference video (`ref/ref.mp4` copied to `assets/ref.mp4`); validated by `validateFormat` (`validate.ts`), rhythm lives in the pace toggle (`PACE` in `lib.ts`) and visuals in the style. `server/scripts/migrate-v9.mjs` rewrites old `format.json` files. A format with `janelas.cut` and `panel` {top} ("Speech Screen") cuts the speaker out only inside those windows (`rvm.py --windows`) and shows him as raw video in a bottom panel elsewhere (`talk.mp4`, scene `cam='panel'` in `kit.py`; `layout_check.mjs` keeps text above the panel). Formats with `hidden: true` in `format.json` stay on disk for old projects (`darkrd-clone`, `explainer-panel`) but leave `listFormats()` and the UI.

**Asset library.** At the end of the script step, `fetchAssets()` (pipeline.ts) asks Sonnet for one search query per moment that gains from a real picture, an icon or a 3D object, searches `server/broll.ts` (Openverse and Wikimedia Commons without a key; Pexels, Pixabay and Poly Pizza with keys from `keys.ts`; Iconify for SVG icons) and downloads the first licensed candidate to `<project>/assets/img/` or `assets/3d/`, listed in `assets/manifest.json` (moment, query, provider, license, author, url). `composeScaffold` copies them to `compose/assets/` together with `workspace/library/{img,3d}/` (a shared library the user fills by hand: 3D icon packs, brand objects) as `compose/assets/lib/`, and the brief prints both lists. `obj3d()` in `kit.py` takes a `.glb` path (GLTFLoader from the CDN, fitted to the box) besides its built-in kinds (cursor, card, layers, bolt, pen, puzzle, calendar, pages, squircle, star, check, cube; two-tone `color`/`color2`, bevelled). The kit also has editor props for product styles: `device()` (phone or laptop in CSS perspective with a screenshot), `ruler()` (numbered rulers, marked `data-layout-decor` so `layout_check.mjs` skips their numbers), `arrow()` (hand-drawn red arrow) and `select_box()` (handles plus a coordinate label).

**Brand fonts and style flags.** `brand.fonts.head.file` is copied to `compose/assets/fonts/font.otf` (weight 600, the whole reel); `brand.fonts.giant.file` (a Black weight) goes to `fonts/giant.otf` and `kit.py` then declares it as weight 900 for `.giant`. `composeScaffold` reads the brand through `writeBrand(st)` (global brand merged with the project override), never the project's stale `brand.json` copy. A motion style's `style.json` may carry `giantCase: "lower"` and `speakerShadow: true` (set by hand after a clone; `cloneStyle` does not write them): `composeScaffold` copies them into `compose.json` and the kit renders lowercase giants and a drop shadow on the cutout.

**UI flow: Vídeo → 1 Ingestão → 2 Roteiro → 3 Revisão → 4 Entrega.** There is no storyboard step and no cards/agent toggle, b-roll option or illustration-pack select in the create dialog: the only per-project choices are the format (the editing layout) and an optional motion style. Approving the script calls `POST /motion`, which goes from the script, the brief and the asset library straight to `compose()`. Internal step names are unchanged (`motion` = Revisão, `final` = Entrega). A project whose state still says `storyboard` (removed step) is moved back to `script` on load. Entrega groups the final render (formats + QA), the After Effects export and the hook copy (embrulhos).

**Transcription.** `transcribe.py` runs the local Whisper of HyperFrames. When the user supplies an `.srt`, the text is the subtitle's but the per-word times come from Whisper on the audio (`transcribe.py <srt> <out> --align <media>`: `align()` matches the words with difflib and spreads the unmatched ones between timed neighbours; if Whisper is missing or matches under half the words, the proportional split of the cue is kept). The kit's word clock (`T('palavra')`) reads those times, so this is what puts words on screen on the beat.

**Revisão (review).** The UI's review step plays `compose/index.html` live in the browser through `<hyperframes-player>` (`engine/hf/`, same HyperFrames 0.8.217 as the render; served at `/hf/*` and `/projects/:id/live/*`), so nothing renders while reviewing. Notes pinned to a time and an optional x/y spot (or `all: true` for the whole video) live in `<project>/review.json`; `POST /review/apply` sends every open note to `compose()` in one call, told to edit only the scenes that cover each note's time, and fails if the agent did not rerun `scenes.py`. `final()` refuses while any note is open or until the reviewer clicks Aprovar (`POST /review/approve` sets `approvedAt`; any new AI pass clears it, manual edits in Edição keep it). Saving notes sends the `version` read with them: a stale one is refused (two tabs).

**Projects are git repos.** Each project is `workspace/projects/<id>/` with its own `.git`; every step and every manual edit commits there. The root repo is not under git. `REELS_HOME` is set to the project folder when spawning scripts, so the scripts read and write inside it.

**Model calls (`server/models.ts`).** `ask()` spawns the `claude -p` CLI with a fixed model per step and effort (`MODEL_BY_STEP` and `EFFORT`: Haiku for triage, Sonnet for brand chat, Opus for everything else: script, motion, reference-reel analysis, brand cloning and the agent composer). Output is forced to a JSON schema and token usage is logged per call. Tools and MCP servers are disabled for these calls. Do not route a new step to a different model without updating that table, since the table is the cost policy.

**Pure logic and validation.** `server/lib.ts` (word spans, time remapping, deep merge, format list, cut windows) and `server/validate.ts` (font/icon/caption-style checks) hold the logic that the tests cover.

**Brands, formats, projects.** `workspace/brands/<id>/` (`brand.json` + `brand.md` + fonts and icons) and `workspace/formats/<id>/format.json` are data, edited through the API or the UI. A project copies the brand and merges per-project overrides with `deepMerge`. `workspace/projects/` is user output. `workspace/styles/<id>/` (`style.json` + `refs/`) are the motion styles cloned from reference reels (`cloneStyle`: beats, palette, camera, motif, GSAP recipes, sound rules); the Estilos tab lists only these. `workspace/library/{img,3d}/` is the shared asset library.

**After Effects export (`server/ae/`).** `exportAfterEffects()` runs `make_jsx.mjs --html <liveDir>/index.html`, which serves that folder on 127.0.0.1, loads it in headless Chrome with the HyperFrames runtime (`engine/hf/hyperframe.runtime.iife.js`) and samples it frame by frame. Video and audio clips go in as their own files (`.webm` becomes ProRes 4444 with alpha), with the camera of the video wrappers as keyframes. Each sub-composition and each manual layer becomes a group of pieces: simple ones become native text and shape layers, and complex ones (images, gradients, masks, emoji, content that changes inside) become ProRes 4444 clips. A `filter: blur()` on the piece itself (caption entries) becomes a Gaussian Blur with keyframes (Blurriness = px × 3.6, measured against Chrome in After Effects); any other filter, or a blur on an inner element, still sends the piece to a clip. Two-colour gradients become a solid with Gradient Ramp (both opaque), Linear Wipe (linear with a transparent end) or a feathered elliptical mask (radial with a transparent end); `<img>` (png/jpg/webp, object-fit fill/contain/cover) is imported as the file, copied to `V/img/` (webp converted to png), with a mask for cover and rounded corners; `mix-blend-mode` on the piece becomes the layer's blending mode (on clips too). A static `<svg>` with plain shapes only (no text, image, filter, mask, gradient, `<use>`, clipPath, or overflow visible) is written to `V/svg/` with its paint resolved from CSS on every child and a bare root (`width` must be the file's first `width=`: After's SVG importer reads the first match, so a root `stroke-width` became width 1); the template imports it under the piece's null and runs Create Shapes from Vector Layer, which keeps the parent, keyframes and in/out. A stroke drawn on by a single dash (the kit's `pathLength=1`, `stroke-dasharray="1 g"`, `stroke-dashoffset` animated to 0), in an svg whose children are all shapes, is written whole and gets a Trim Paths on its group (the conversion makes one group per child in reverse order) with End keyed to the visible fraction per frame; any other dash pattern keeps the piece a clip. Note that GSAP rounds `strokeDashoffset` to whole px, so with `pathLength=1` the kit's strokes pop at mid-tween instead of drawing, in the video too. Text drawn on `<canvas>` (the compose engines' `fillText`) is captured per frame through a hook on the canvas context and becomes native text layers with keyframes; the clip then carries only the decoration. When the composition has a world camera (`#world` with `preserve-3d` and depth layers with `translateZ`, written by `compose/kit.py`), everything is measured with that camera at rest and the comp gets a Camera plus 3D nulls (world pose keyframes, one null per depth) that the scene layers hang from. `server/test/ae_export.test.ts` runs the exporter on `server/test/fixtures/ae/index.html` (DOM text, canvas text, world camera) and `exportAfterEffects` fails when the report has text in the composition but no native text layer: when `kit.py` adds a new wrapper, canvas kind or way of writing text, add it to that fixture. `build_comp.template.jsx` builds the comp in z-index order, and `run.jsx` saves the `.aep` (the pipeline runs it through `osascript`). Timeline organisation (in `build_comp.template.jsx`): every visible layer gets its anchor point at the centre of its own content (`ancoraNoCentro`, position compensated; canvas-text keys compensated by R·S·anchor; clips at half the file size); piece control nulls are label Orange (11) and shy; the world null, depth nulls and camera are also locked at the end of the build, and `comp.hideShyLayers` is on. The piece null keeps its anchor at the CSS transform origin on purpose (it is the pivot the piece scales and rotates around). Output goes to `<project>/after-effects/`, which is gitignored.

**Tooling outside the server.** `tools/vision_cutout.swift` (macOS Vision person cutout) is standalone and not called by the server.

## Notes

- The server binds to `127.0.0.1` only and has no auth; it assumes a single local user. Do not expose it. It rejects any `Host` or `Origin` that is not 127.0.0.1/localhost and any non-GET request that is not `application/json` (except `/upload`), so a web page on another site cannot drive it; send `-H 'content-type: application/json'` with curl.
- Naming is inconsistent: the root README says "Editor 7.0", `server/README.md` and commit messages say "Editor 4.0". Treat the code as authoritative.
- `VERSAO` (repo root, e.g. `00.20`) is the version shown next to "Editor 7.0" and on Configurações → Atualização (installed vs GitHub). Bump the last number in the same commit whenever something goes to `main` (00.20 → 00.21), so a user can tell whether an update landed. The self-update (`checkUpdate`/`applyUpdate` in pipeline.ts) uses `git pull --ff-only` on clones, which removes files deleted upstream; ZIP installs get the GitHub tarball overlaid, and files a previous update installed that the new one no longer ships are removed using `.arquivos-instalados` (never anything under `workspace/`).
